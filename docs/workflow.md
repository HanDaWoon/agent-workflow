# 워크플로우 구조

Agent Workflow는 공통 실행 절차를 제공하고, 프로젝트별 도구·검증·권한은 해당 프로젝트의 지침을 따릅니다. 사용자의 현재 요청과 호스트의 권한이 우선하며, 플러그인 설치 자체가 외부 발행이나 에이전트 위임을 승인하지 않습니다.

## 책임 구분

| 계층 | 소유하는 내용 |
| --- | --- |
| 전역 진입 지침 | 작업 분류, 공통 실행 스킬로 진입하는 조건, 언어와 권한 원칙 |
| 실행 스킬 | 계획·실행·검증·리뷰·완료 경로, 역할과 변경 소유권, 증거 연결 |
| 프로젝트 설정 | 이슈 tracker, 기준 branch, 검증 명령의 원본, 자원 격리, 통합·배포 조건 |

기존 프로젝트 문서를 우선 연결합니다. 설정 파일이 없으면 저장소와 CI에서 필요한 값을 확인하고, 실행을 막는 빈칸만 질문합니다. 별도 설정 문서를 만드는 것을 모든 작업의 선행 조건으로 삼지 않습니다.

## 요청에 따른 경로

| 요청 | 처리 |
| --- | --- |
| 질문·읽기 | 필요한 근거를 확인하고 답변 |
| 설계·검토 | 합의된 조건과 미결정을 구분한 검토안 |
| 명확한 구현 | 이슈와 수용 기준 확인 후 단일 실행 |
| 불확실한 구현·분해 | 막는 결정부터 확인하고 가까운 실행 단위 정의 |
| 감독·진행 추적 | Orca orchestration으로 작업자와 의존성 관리 |
| 새 세션으로 소유권 인계 | Orca CLI 인계 경로 사용 |

## 기본값

- **진입:** 구현·재개·작업 계획을 대상으로 합니다. 실제 자동 진입은 호스트의 스킬 선택과 프로젝트 지침에 달려 있습니다.
- **리뷰:** 작은 문서·저위험 변경은 자기 검토, 일반 구현은 독립 검토자 1명이 Spec·Standards를 검토합니다. 보안·데이터 손실·동시성 등 고위험 변경은 축별 검토자를 분리합니다. 검토자 수가 위임 권한을 대신하지 않습니다.
- **병렬도:** 일반 세션은 단일 실행입니다. 감독 실행은 독립 구현 최대 2개부터 시작하고 자원 충돌·리뷰 대기 등 실제 근거로 조정합니다.
- **종료:** 목표 branch에 통합하고 필수 검증·리뷰 증거를 확보한 뒤 이슈를 종료합니다. 배포가 수용 기준이면 배포 증거도 필요합니다.
- **외부 도구:** 설치된 전문 스킬과 Orca의 현재 호출 계약을 사용합니다. 설치·업데이트·원본 복제를 맡지 않습니다.
- **프로젝트 설정:** Markdown과 기존 설정 링크로 필요한 값을 연결합니다.
- **모델:** 난이도·불확실성·영향 범위로 선택하고 지원값과 실제 적용값을 확인합니다. 호스트 간 같은 effort 이름을 동등한 추론량으로 간주하지 않습니다.

세부 절차는 [실행](../plugins/agent-workflow/skills/engineering-workflow/references/execution.md)과 [완료](../plugins/agent-workflow/skills/engineering-workflow/references/completion.md)가 소유합니다. 완료 자원 정리는 완료 절차의 일부이며 현재 사용 중인 자원과 고유 증거는 보존합니다.

## Matt 스킬과 Orca

Matt Pocock 스킬은 계획·테스트·설계·리뷰 등의 전문 기법을 담당합니다. Agent Workflow는 해당 기법을 언제 호출하고 작업·역할·완료 증거에 어떻게 연결할지를 담당합니다. Orca는 감독 실행의 Task·Dispatch·작업자·워크트리 상태를 담당합니다.

전문 스킬의 사용자 전용 호출 조건은 그대로 지킵니다. 실행 소유자는 한 흐름으로 정하며 서로 다른 구현 흐름을 중첩하지 않습니다. 자세한 연결 조건은 [스킬 조합](../plugins/agent-workflow/skills/engineering-workflow/references/skill-composition.md)에 있습니다.

## 배포 구조

`plugins/agent-workflow/`가 배포 단위입니다. 두 호스트의 manifest는 같은 스킬 본문·references·한국어 보고 assets를 사용합니다. 루트 `skills/` 링크는 기존 개발용 원본 포인터와의 호환성을 제공합니다. 설치 캐시는 이 링크에 의존하지 않습니다.

저장소에서 직접 읽는 개발용 연결과 호스트의 플러그인 캐시 설치는 갱신 방식이 다릅니다. [설치 안내](agent-setup.md)의 사용 방식에 맞춰 관리합니다.
